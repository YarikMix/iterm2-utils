# iterm2-utils: настройка iTerm2 для Codex и Claude Code

Статус: проверка полноты пройдена; согласована пользователем переходом к writing-plans.
Дата: 22 октября 2026, МСК.
Репозиторий назначения: публичный `https://github.com/YarikMix/iterm2-utils`.

## 1. Зачем и для кого

Коллега установил iTerm2 и пользуется Codex CLI, Claude Code или обоими агентами.
Он передаёт агенту ссылку на репозиторий и просит настроить iTerm2. Агент выясняет,
какие улучшения нужны, выполняет доступную настройку, проверяет результат и
объясняет только оставшиеся ручные действия. Коллеге не требуется разбираться
в JSON-профилях, путях к Python, hooks и последовательности установки компонентов.

Один публичный репозиторий должен содержать поддерживаемый комплект утилит,
документацию и один совместимый с обоими агентами скилл настройки. Для установки
не должны требоваться корпоративный GitLab, PAIW, личные файлы автора или его Mac.

## 2. Решения пользователя

- Работаем по SDD: brainstorming, согласованная спецификация, план, реализация.
- Репозиторий `YarikMix/iterm2-utils` публичный.
- Агент сначала уточняет у коллеги, какие фичи подключить; не устанавливает весь
  набор молча и не считает отсутствие ответа согласием.
- Доступные действия выполняет сам. Если нужен UI, использует доступный Peekaboo.
  Если Peekaboo отсутствует, даёт коллеге точные инструкции для ручного шага.
- В первую версию включаются все семь фич из раздела 4.
- Clipboard Trace остаётся инструментом разработчика, не частью обычной установки.

Остальные конкретные решения ниже — предложения автора спецификации для
согласования, а не ранее высказанные пользователем требования.

## 3. Сценарий настройки

1. Агент читает скилл из репозитория и выполняет диагностику без изменения настроек.
2. Определяет ОС, iTerm2 и его путь, доступные агенты и версии, Python, оболочку,
   существующие компоненты пакета, конфликты и доступность Python API/Peekaboo.
3. Показывает список фич с коротким описанием и применимостью к найденным агентам.
   Один вопрос позволяет выбрать несколько фич; произвольный ответ допустим.
   Если выбор уже явно дан в запросе, не спрашивает его повторно.
4. Показывает краткий конкретный план: какие компоненты и зависимости будут
   установлены, какие собственные блоки конфигурации добавятся, какие нужны UI-шаги.
   Ответ с выбором фич разрешает обычные необходимые действия внутри их настройки;
   не вводить дополнительные подтверждения для каждой записи файла.
5. Выполняет настройку выбранного набора. Зависимости выбранных фич объявляет
   до установки; если подходящего способа установить зависимость нет, сообщает
   точный недостающий компонент, а не ломает остальную установку.
6. Для UI предпочитает доступный штатный API/CLI, затем Peekaboo. Без доступного
   UI-инструмента даёт локализованный путь по меню и название кнопки. После ответа
   коллеги повторно проверяет состояние вместо предположения об успехе.
7. Проверяет файлы, активную регистрацию и доступные runtime-признаки. Финальный
   отчёт разделяет «подключено и проверено», «настроено, нужна новая сессия» и
   «ожидает ручного шага». Успешная запись JSON сама по себе не доказывает работу.

Системные разрешения и штатные подтверждения доверия hooks подтверждает человек.
Peekaboo не устанавливается скрытно, его отсутствие не мешает остальной настройке.
Права Screen Recording/Accessibility, foreground-grants и Python API проверяются
раздельно; отказ инструмента не обходится альтернативным способом управления UI.
Перед открытием собственного окна агент предупреждает; закрывает только свои окна.

## 4. Набор фич первой версии

### 4.1. Копирование в Codex

- Отдельный Dynamic Profile наследует выбранный существующий профиль пользователя.
  Не заменяет цвета, шрифты и общий `Default` экспортом с компьютера автора.
- Автоматическое переключение по foreground-программе `codex`, правило `&codex`.
  При выходе из Codex восстанавливается предыдущий профиль там, где переход был
  выполнен автоматическим переключением. При запуске вкладки сразу с профилем
  Codex предшествующего профиля для возврата может не быть.
- Для физической клавиши C в английской/русской раскладках Ctrl+C передаёт `0x03`,
  Cmd+C — `ESC[99;9u`. Не добавляет Enter, Tab, клики или отдельный автофокус.
- При наличии внутреннего выделения ручное копирование обрабатывает сам Codex.
  Без выделения сохраняется штатный смысл Ctrl+C. Cmd+V остаётся обычной вставкой.
- Включение этой фичи также означает отключение автокопирования при выделении:
  `tui.copy_on_select = "never"` в Codex и `CopySelection = false` в iTerm2.
  Об этом изменении общей настройки iTerm2 агент сообщает в плане; прежнее значение
  сохраняется для условного восстановления при удалении.
- Поддержка Cmd+C/Ctrl+C для Claude Code не предполагается идентичной: Codex-профиль
  никогда не назначается `claude`. Для Claude эта конкретная фича показывается как
  Codex-only; штатное копирование Claude не переопределяется.
- Не обещать исправление исходной гонки clipboard на любом объёме. В текущей
  настройке подтверждены ручное копирование и раскладки, а не гарантия времени
  завершения записи. Задержка вставки не входит в эту фичу.

### 4.2. Статусы сессий

- Для Codex используются существующие observational hooks `iterm2-status`:
  working/waiting/idle и цветные индикаторы у конкретной сессии, Session Status.
- Интерактивные запуски Codex используют `--no-daemon`, если версия его поддерживает:
  общий daemon иначе может выполнять hook с окружением другой вкладки.
  Исключения `agents`, `remote-control`, `app-server` сохраняются. Агент объясняет
  ограничение доступности daemon-зависимых возможностей для интерактивного запуска.
- Для Claude Code используется штатная интеграция iTerm2 с `cc-status` и её штатным
  установщиком. Не устанавливать параллельно второй обработчик тех же статусов.
  Workgroup и автоматическое создание Diff/Review-вкладок не включаются без выбора
  пользователя: выбранная фича — статусы, а не вся необязательная интеграция.
- Hooks адресуют явный UUID вкладки. Не выбирают активную вкладку как запасной путь,
  не меняют разрешения инструментов и не сохраняют prompts, команды или их вывод.

### 4.3. Уведомления macOS

- Самостоятельная опция: завершение задачи, запрос ответа/разрешения, переход к
  соответствующей вкладке по нажатию; без повторов одного и того же события.
- Для Codex сохраняется проверенное поведение публичного форка `iterm2-status`:
  уведомление не показывается, если нужная вкладка уже перед пользователем.
- Для Claude Code отдельный адаптер использует официальные lifecycle hooks; он
  должен отличать завершение от прерывания и не подменять пользовательские hooks.
  Точный mapping событий и исключения версий фиксируются в плане после сверки
  официальной схемы. Поддержку нельзя считать выполненной одной записью конфига.
- Отдельно от установки статусов; включение одних уведомлений может подключить
  необходимый runtime, но не означает включение всех видимых фич статусов.
- Нужные зависимости, включая `terminal-notifier` и подходящий Python, обнаруживаются
  автоматически. Не переписывать существующие сторонние уведомления без отдельного
  решения: конфликт обозначается; не публиковать PAIW-хуки как зависимость пакета.

### 4.4. Восстановление сессий Codex

- Переносимый модуль с поведением существующего `codex resume --restore`: выбор
  нескольких сохранённых основных разговоров, первый в текущей панели, остальные
  в новых вкладках с сохранёнными рабочими каталогами и `CODEX_HOME`.
- По умолчанию при выбранной фиче предлагает список один раз после запуска iTerm2;
  сам разговоры не запускает, пока человек не подтвердил выбор.
- Пропускает уже открытые и недоступные записи; фоновые агенты и служебные процессы
  в список не входят. Обычный `codex resume --all` не меняет смысл.
- Сохраняет метаданные, не копирует переписки. При неизвестном исходе открытия
  вкладки не повторяет запуск вслепую. Геометрия окон и сплитов не восстанавливается.
- Работает совместно с оболочкой статусов, без конкурирующих функций `codex`.
  При выборе только восстановления выполняется необходимый запуск без daemon.
- В первой версии эта фича относится только к Codex; Claude Code агент показывает
  это ограничение. Старый отключённый `claude-resume` не возвращается автоматически.

### 4.5. Доступ агента к iTerm2 через MCP

- Отдельная выбираемая фича для Codex и/или Claude Code. Python API iTerm2 является
  её предпосылкой, а не разрешением включать её при выборе других фич.
- Объяснить, что агент получает доступ к тексту терминальных сессий и ограниченным
  операциям вроде заголовков/бейджей. Использовать проверенный ограниченный
  `mcp-server-iterm2`, а не произвольное исполнение shell через терминал.
- Версия runtime и ограничения зависимостей фиксируются: текущая проверенная
  установка — `mcp-server-iterm2==0.1.1` с `mcp<2`.
- Регистрация через поддерживаемые механизмы конкретного агента; не заменять весь
  файл MCP-настроек. Не читать и не копировать чужие auth/env-блоки в диагностику.
- Конфликт одноимённого сервера требует понятного решения, а не перезаписи.
  Проверка запуска процесса и проверка живого соединения — разные результаты.

### 4.6. Shell integration

- Используется официальный скрипт iTerm2 для zsh: отметки команд, текущий каталог,
  переходы между командами. Уважать уже установленную shell integration.
- Подключение ограничено iTerm2, не влияет на другие терминальные приложения.
- Не копировать весь `.zshrc`, тему, prompt, PATH и личные настройки автора.
  Повторная установка не создаёт повторного source.
- Лицензия и происхождение официального скрипта сохраняются; источник закреплён
  версией/контрольной суммой, а не исполняемым `curl | sh`.

### 4.7. Дополнительные горячие клавиши

Каждая опция выбирается отдельно, с объяснением до применения:

- Ctrl+V на русской раскладке передаёт ASCII Ctrl+V; в Codex это вставка изображения.
- Alt+Enter передаёт соответствующее сочетание для переноса строки там, где агент
  его поддерживает; совместимость проверяется по установленной версии.
- Ctrl+Q посылает два Ctrl+C; обозначить как потенциальное прерывание/выход.
- Cmd+Shift+R вводит `/resume` и фактический перевод строки. Локальная старая запись
  содержит экранирование; перед переносом проверить байты, не тиражировать ошибку.

Новые bindings применяются в соответствующих профилях агента, не глобально к shell.
Если фича копирования не выбрана, дополнительный профиль может содержать только
выбранные hotkeys, без Cmd+C/Ctrl+C и без отключения copy-on-select. Существующее
сочетание с другим действием не перезаписывается без согласованного разрешения.

## 5. Устройство репозитория и скилла

- Один стандартный `skills/iterm2-setup/SKILL.md` с краткими инструкциями и ссылками
  на предметные references; подходит Codex и Claude Code, не зависит от superpowers
  или PAIW у конечного пользователя.
- В README есть начальный сценарий «передай агенту эту ссылку» и точные способы
  обнаружения/установки скилла обоими агентами. Самостоятельно читаемая инструкция
  работает и до появления скилла в списке инструментов текущей сессии.
- Детерминированные утилиты выполняют проверку, планирование, установку, doctor,
  обновление и удаление; скилл не собирает конфигурацию одноразовыми командами заново.
- Общая настройка — Python, оболочка — zsh. Требования к версиям проверяются по
  выбранным фичам; существующие исправные интерпретаторы не заменяются без нужды.
- Используем существующие компоненты. Публичный код статусов берётся из
  `YarikMix/iterm2-status` с сохранением MIT attribution; самостоятельно переносится
  только относящийся к задаче код восстановления и его тесты. Не копировать
  репозитории, private settings, переписки и внутренние материалы целиком.
- Runtime-компоненты и необходимые ресурсы доступны из этого публичного репозитория;
  у коллеги нет скрытого шага клонирования корпоративного репозитория. Версии внешних
  зависимостей и происхождение перенесённого кода записаны явно. Не использовать
  mutable-ветку как единственную гарантию версии устанавливаемого runtime.
- Машинные пути вычисляются на месте. В опубликованном коде нет домашних путей автора,
  локальных UUID сессий, корпоративных URL и настроек авторизации.
- Clipboard Trace, личные PAIW-хуки, Karabiner и старый Claude resume не устанавливаются.

## 6. Существующие установки, обновление и удаление

- Read-only диагностика распознаёт нашу текущую установку и новые установки пакета.
  Наличие внешнего компонента не означает, что пакет владеет им и может удалить.
- Обновление работает только с собственными записями и управляемыми блоками.
  Чужие hooks, профили, plugins, MCP-серверы и настройки агента сохраняются.
- Перед изменением собственных существующих файлов сохраняются приватные backups;
  при неуспехе выполняется откат собственных изменений текущего шага. Результат
  составной операции отражает уже выполненные и ожидающие шаги отдельно.
- Установка идемпотентна. Поддерживаются пути с пробелами/Unicode, symlinks к
  `.zshrc`, нестандартный `ZDOTDIR`, `CODEX_HOME`, место приложения и интерпретатора.
- Удаление убирает только принадлежащие пакету компоненты и восстанавливает прежние
  значения лишь если пользователь не поменял их после установки. Переписки,
  пользовательские файлы и backups не удаляются.
- Для существующего `codex-iterm2-status` не ставится вторая копия hooks. Диагностика
  предлагает reuse или явную миграцию; выбор миграции не подразумевается запросом
  включить другую фичу. Старые репозитории и текущая рабочая установка автора при
  разработке нового пакета не изменяются.
- Вызовы сети, subprocess и API ограничены по времени; неизвестный результат не
  превращается в автоматический повтор запуска GUI/сессии или повторную регистрацию.

## 7. Диагностика и поддержка

Doctor имеет читаемый человеком и машинный результаты. Отдельные состояния:
готово, отсутствует зависимость, конфликт настроек, нужен UI-шаг, нужна новая сессия,
runtime-связь недоступна. Диагностика по умолчанию не изменяет файлы и не открывает
вкладки. Публичный отчёт не содержит терминальный текст, prompts, секреты, полный
environment или чужие MCP credentials; подробные локальные пути выводятся только
там, где нужны пользователю для исправления.

Недоступность одной фичи не представляется успехом всего пакета. Агент продолжает
независимые разрешённые шаги и даёт инструкции только для оставшихся действий.
Обновление и удаление доступны через тот же скилл и документированные команды.

## 8. Проверка и критерии приёмки

1. Чистый временный HOME, установлен только Codex: выбор clipboard/status создаёт
   только необходимые компоненты; Claude не требуется. Аналогичный сценарий только
   с Claude не требует Codex и не создаёт Codex-only hooks/профиль.
2. Оба агента установлены: независимый выбор фич, сохранение чужих hooks/настроек;
   повторная установка не добавляет дубликатов. Невыбранные фичи не включаются.
3. Dry-run/doctor не изменяют файлов, не открывают UI и не меняют hook trust.
4. Ошибка записи/CLI, прерывание, конфликт, повреждённый JSON/TOML и неизвестный
   результат открытия вкладки не повреждают чужие настройки и дают точный отчёт.
5. Update/uninstall проверены с пользовательскими изменениями после установки:
   удаляется только собственное, новое чужое значение не затирается старым backup.
6. Скилл проходит структурную валидацию и независимые поведенческие сценарии:
   чистая установка, выбор части фич, нет Peekaboo, UI-отказ, уже установленный
   компонент. Проверяется действие/артефакт, а не совпадение формулировок инструкции.
7. Живая приёмка в изолированном контуре Mac: две раскладки и ручное копирование
   Codex; автоматическое включение профиля при старте и возврат после выхода;
   working/waiting/idle; уведомление и переход в правильную вкладку; выбор и
   восстановление сессий; живое MCP-чтение; shell marks; выбранные hotkeys.
8. Мок-тесты не называются живой приёмкой. Если нельзя проверить чистый Mac или
   определённую версию, в README перечисляется реально проверенная матрица.
9. Перед публичной публикацией проверяются содержимое пакета, лицензии/attribution,
   отсутствие локальных файлов, личных путей и внутренних зависимостей. GitHub
   репозиторий создаётся и публикуется после согласования спецификации и исполнения
   плана, в рамках уже данного запроса пользователя.

## 9. Что не входит

Windows/Linux, другие оболочки как полноценная цель первой версии, установка или
пересборка самого iTerm2, установка/авторизация самих Codex и Claude Code, миграция
чужих учётных данных, универсальная настройка остальных MCP и гарантия устранения
гонки clipboard на любом размере текста. Недостающий агент — понятная инструкция,
а не скрытая установка второго продукта.

## 10. Что решает разработчик при планировании

Точные имена CLI-флагов и файлов состояния; внутреннее разбиение модулей; способ
упаковки публичных исходников без дублирования владения; зависимости и минимальные
версии по capability checks; конкретный mapping Claude hooks для уведомлений;
минимальная достаточная форма installation receipts; CI на временном HOME и
подготовка изолированной живой проверки. Эти решения не могут расширить согласованный
набор фич, автоматически включать опции или выдавать непроверенное за поддержанное.

## 11. Источники и текущая доказательная база

- Локально проверены профиль копирования с правилом `&codex`, два типа copy-bindings,
  `tui.copy_on_select = "never"`, Python hooks статусов и отдельный MCP runtime.
  Исходная гонка на произвольном объёме не доказана устранённой.
- Проверенная конфигурация автора: iTerm2 3.7.6, Codex 0.163.0. Это свидетельство,
  а не автоматически минимальная версия для каждой фичи.
- https://iterm2.com/documentation-session-status.html — способы задания статусов,
  Session Status и адресация через `it2`.
- https://iterm2.com/claude-code-integration.html — встроенные hooks Claude,
  Python API, отдельные необязательные шаги Workgroup.
- https://code.claude.com/docs/en/skills — стандартный формат `SKILL.md` и поддержка
  общих Agent Skills. Точные способы установки скилла Codex сверяются при плане
  с доступной официальной документацией/текущим skill-installer.
- https://github.com/YarikMix/iterm2-status — публичный форк существующего runtime.
