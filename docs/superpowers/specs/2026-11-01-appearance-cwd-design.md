# Цвет и иконка вкладки при смене каталога

Статус: утверждена пользователем переходом к `superpowers:writing-plans`
01.11.2026; подход `chpwd` выбран отдельно. База: `origin/main`, `237b151`.

## Зачем

Обычный сценарий пользователя: открыть вкладку в общей папке, затем выполнить
`cd` в репозиторий. Цвет и составная иконка должны показывать текущий проект
сразу после перехода, без запуска Codex или повторного запуска shell.

## Выбранное поведение

- Вход в зарегистрированный корень или его подкаталог назначает цвет и иконку
  этого правила. Переход между репозиториями меняет оба свойства.
- Выход из всех зарегистрированных корней возвращает стандартный вид вкладки:
  отключается назначенный Tab Color, кастомная иконка скрывается. Не задавать
  конкретный «дефолтный» RGB: обычный вид зависит от профиля и темы iTerm2.
- Назначение и сброс учитывают base/light/dark варианты цвета. Меняются только
  сессионные свойства цвета и иконки; профиль, фон, заголовок и глобальный
  Default остаются под управлением iTerm2.
- Используются прежние JSON-правила, семь встроенных и пользовательские PNG,
  физические корни, границы путей и приоритет вложенного корня. Недоступный
  корень не совпадает; каталоги на отключённом диске не создаются.
- Старт shell сразу применяет состояние для её текущего каталога. При смене
  каталога обновляется только собственная интерактивная zsh-сессия iTerm2.
  Команды модели в subprocess и неинтерактивные shell вкладку не перекрашивают.
- Существующие интерактивные запуск/возврат Codex и restore сохраняют оформление
  при штатных APS-переходах; `cd` самого пользователя больше не оставляет цвет
  покинутого репозитория.

Это явно заменяет ограничения предыдущей спецификации
[repo appearance](2026-11-01-repo-appearance-design.md): «обычный cd не меняет
оформление», «при отсутствии совпадения существующее оформление не меняется» и
«chpwd hooks не нужны». Здесь отсутствие совпадения означает стандартный вид.

## Подходы

1. **Выбран пользователем: штатный zsh `chpwd` и существующий helper.**
   Переиспользуются правила, официальный API iTerm2 и общий lifecycle пакета;
   событие shell меняет только цвет и иконку своей сессии.
2. **Automatic Profile Switching с профилями проектов.** Меняет целый профиль,
   требует дополнительных профилей и согласования с существующим `&codex`.
   Пользователь выбрал расширение текущего helper.

## Границы реализации

Предложение исполнителя: это новое поведение уже включённой функции `appearance`,
без отдельного режима, CLI-флага или изменения схемы JSON. Установка остаётся
явной через существующий CLI и сохраняет персональные правила/остальные функции.

Хук регистрируется один раз штатным механизмом zsh, не подменяет чужие `chpwd`
и не дублируется при повторном source. Используются существующие ограниченный
helper и его отмена/очистка: быстрые последовательные переходы должны оставлять
последнее оформление, без позднего перекрашивания старой задачей. API-ошибка
не отменяет успешный `cd`; постоянный наблюдатель, демон и polling не добавляются.
Не расширять поддержку tmux, других shell/агентов или поздних APS-переходов.

## Проверки и поставка

Проверить вход, переход между корнями, подкаталоги, выход в общую папку и скрытие
иконки; light/dark значения сброса, повторный source/чужие hooks, быстрые `cd`,
ошибки API, собственный UUID, APS и restore. Разработка использует hermetic HOME,
fake adapters и существующие тесты. Обновить документацию и проверки доставки;
пройти обязательные unittest/shell/source/skill/export/release проверки.

После реализации и review обновить локально только согласованный `appearance`
по plan/dry-run и отдельно проверить обычный `cd` в собственных временных вкладках.
Пользовательские вкладки не перезапускаются, личные пути/правила не публикуются.
