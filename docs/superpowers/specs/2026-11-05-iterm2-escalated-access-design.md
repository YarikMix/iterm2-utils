# Операционный режим запуска iTerm2 из Codex

**Статус:** дизайн подтверждён пользователем 05.11.2026.

## Цель

Убрать повторяющиеся ошибки `Operation not permitted` при обращении к приватному сокету iTerm2 из песочницы Codex.

## Объём

Расширенный доступ применяется сразу к read-only инвентаризации iTerm2, scoped `session get-var`, чтению профиля и единственному вызову `launch-codex`.

## Решение

Операции запускаются через `require_escalated` с узкими префиксами для bundled `it2` и проверенного Python `iterm2-utils`. Обычный sandbox-вызов перед ними не выполняется.

## Не входит в задачу

Репозиторий `iterm2-utils`, настройки Magic, профиль iTerm2, Python SDK и host sandbox policy не изменяются. Автоматическое повышение прав внутри Python не добавляется.

## Критерии успеха

- первый вызов `session/tab/window/profile` проходит без `Operation not permitted`;
- `launch-codex` получает тот же расширенный контекст;
- проверка созданной вкладки выполняется только в том же разрешённом контексте;
- используются узкие префиксы, а не полный доступ к системе.

## Распространение правила в скиллы

### Намерение

Зафиксировать операционный режим в публичных инструкциях, чтобы следующий Codex-агент не делал первый пробный вызов iTerm2 из обычной песочницы и не получал ложный `Operation not permitted`.

### Объём

Добавить короткое условное правило в оба независимых скилла:

- `skills/iterm2-setup/SKILL.md` — для `doctor --live`, `reconcile` и других вызовов, которые обращаются к iTerm2 API;
- `skills/iterm2-launch/SKILL.md` — для `it2` inventory/observation и единственного `launch-codex`.

Правило действует только при запуске из Codex с поддержкой `require_escalated`. Вызовы из других хостов не получают несуществующий для них параметр.

### Поведение

- расширенный контекст применяется до первого вызова `it2` или Python API;
- предварительный вызов в обычной песочнице запрещён;
- используются только узкие разрешённые префиксы bundled `it2` и проверенного Python launcher;
- недоступный escalation считается блокировкой и не вызывает автоматического повтора.

### Не входит в задачу

Не меняются CLI, Python-код, bootstrap bundle, iTerm2 settings, Magic, host sandbox policy и глобальная память пользователя. Общий reference-файл не добавляется: два коротких локальных правила дешевле изменения bundle/bootstrap-механики.

### Подходы

Рассмотрены: правило только в troubleshooting (слишком поздно для первого вызова), общий reference-файл (лишняя механика для четырёх строк) и короткие условия в обоих SKILL.md. Выбран последний вариант, потому что `iterm2-setup` и `iterm2-launch` устанавливаются и читаются независимо.
