# Надёжный запуск и восстановление Codex в iTerm2

Статус: проект для согласования. База: `origin/main`, `e90b3320478d815baa693e23f4e51419b0ce4da7`.

## Цель и выбранный подход

Агент открывает одну вкладку iTerm2 с нужным профилем и рабочим каталогом: либо для нового Codex с поручением из handoff, либо для продолжения конкретного существующего диалога. Команда запуска не должна попадать текстом в поле ввода уже работающего Codex.

Пользователь выбрал одну консольную подкоманду `launch-codex` с двумя взаимоисключающими режимами: `--handoff FILE` и `--resume UUID`. Новых поручений восстановленному диалогу автоматически не отправляем.

Рассмотренные подходы:

1. Одна команда с общими проверками и двумя режимами — **выбрано пользователем**. Сохраняется существующий вызов с handoff, а исправление транспорта применяется к обоим режимам.
2. Отдельная `resume-codex` — отклонено: ещё одна почти одинаковая команда и документация.

Правка только текста скилла недостаточна: существующая CLI-команда тоже использует проблемный транспорт. Создание через официальный Python SDK iTerm2 — предложение автора, включённое в этот проект спецификации.

## Наблюдения и исправляемое прежнее решение

В спецификации `2026-11-01-codex-launch-design.md` предполагалось, что `it2 tab new --command` заменяет стартовую команду профиля. В живом запуске 01.11 созданная вкладка исполняла собственную команду профиля (пустой Codex), а переданный запуск оказался в его поле ввода. Это повторилось и для команды восстановления. Такой транспорт больше не используем для `launch-codex`.

В том же окружении `Window.async_create_tab(profile=..., command=...)` официального SDK создал вкладку с настоящей командой процесса. `codex resume` открыл найденный диалог; проверены аргументы процесса и восстановленная переписка. Это доказательство конкретного resume-сценария, не приёмка будущей реализации с handoff.

В инструкции также ошибочно требуется равенство `processTitle` и `commandLine`. Существующий код ожидает `processTitle` плюс аргументы. Приводим скилл к корректному контракту, не ослабляя проверку полного запуска.

## Интерфейс

```text
python3 -m iterm2_utils launch-codex \
  --window WINDOW_ID --profile PROFILE_NAME --cwd ABS_DIR \
  (--handoff ABS_FILE | --resume SESSION_UUID) --json
```

- `--window`, `--profile`, `--cwd` обязательны в обоих режимах; ровно один из `--handoff` / `--resume` обязателен.
- Существующий корректный вызов с handoff остаётся совместимым. Одновременные режимы, отсутствие режима и невалидный UUID отклоняются до создания вкладки.
- `--resume` принимает только точный UUID; нет `--last`, выбора по имени, интерактивного picker, fork или произвольного prompt.
- `--cwd` определяет рабочую папку и для resume. Скилл по умолчанию берёт подтверждённую папку найденного диалога; другую передаёт только по указанию пользователя. Нельзя молча подставлять текущий каталог агента.
- В режиме handoff стартовый argv остаётся `codex -C ABS_DIR <существующее поручение прочитать handoff>`.
- В режиме resume argv: `codex resume SESSION_UUID -C ABS_DIR`, без нового поручения.
- Для оболочки сохраняются штатная функция `codex`, настройки, модель, endpoint и поддерживаемые wrappers. Переменная `CODEX_RESTORE_NO_AUTO=1` задаётся до запуска login shell только для нового процесса. Не добавляем `--no-alt-screen`, flags обхода защит или overrides модели/API.

## Проверки до создания вкладки

Сохраняются проверки macOS, Codex/zsh, эффективного конфига, поддерживаемого wrapper, точного окна и уникального профиля/GUID, материализованных EN/RU bindings, CopySelection, режима TUI, существующего абсолютного cwd и защита от shell-инъекций. Выбранный bundle `it2` остаётся средством read-only наблюдения, но наличие `tab new --command` в его help больше не является проверкой транспорта создания.

Новый prerequisite: официальный модуль `iterm2` доступен именно Python 3.11+, которым запущена CLI. Он импортируется лениво только для запуска, как уже сделано у appearance. Остальные команды и установка скилла не должны начать требовать SDK. При отсутствии SDK, недоступном API или отказе доступа — ограниченная диагностика `blocked` до мутации, без установки зависимостей, выдачи разрешений или перехода к другому транспорту. В README/скилле явно указать этот prerequisite и поддержанную при проверке версию SDK; частный путь к Python автора не включать в продукт. CLI не ищет произвольные окружения и не запускает `pip`/`uv` автоматически.

Handoff сохраняет текущую проверку обычного читаемого файла без symlink/FIFO. Resume после определения эффективного `CODEX_HOME` проверяет существование интерактивного диалога по точному UUID: только совпадающий журнал внутри `CODEX_HOME/sessions`, проверка его заголовка через существующие helpers `transcripts.normalize_uuid` / `transcripts.validate` либо минимальное их расширение. Полные тексты остальных диалогов не читаются. Нет валидного единственного совпадения — `blocked`; не запускаем пустой новый Codex вместо resume. Заголовок содержит исходный cwd и не запрещает явно переданный другой существующий cwd.

Скилл при поиске диалога подтверждает совпадение по содержанию относящейся к задаче истории. Если уже установлено, что тот же диалог открыт, сообщает его вкладку; второй экземпляр открывает только по явной просьбе. Новый менеджер блокировок/сессий в CLI не добавляем.

## Единственное создание через API

После проверок SDK адресует окно по явному ID, повторно убеждается в доступности выбранного профиля/GUID и вызывает `Window.async_create_tab(profile=..., command=...)` ровно один раз. Этот метод задаёт custom command создаваемой сессии; текст не отправляется через `session send/run` или `async_send_text`.

Профиль применяется при создании. Глобальные настройки профиля не переписываются. Построение shell-команды, identity guard и сохранение вкладки после завершения процесса переиспользуются из существующей реализации. Все значения проходят существующие quoting-границы.

Адаптер возвращает точные window/tab/session IDs из результата SDK. Затем read-only инвентарь подтверждает, что это единственная сессия именно созданной вкладки выбранного окна. UUID iTerm2 сравниваются в нормализованном виде; `it2` получает поддерживаемое представление UUID, без угадывания по недавности или активному окну.

Все внешние операции ограничены по времени: подключение/preflight — до 10 секунд на операцию; создание и последующее подтверждение имеют общий бюджет 30 секунд. Внутренние процессы ограничиваются оставшимся бюджетом; stdout не содержит полный argv, handoff, настройки или секреты. Подробности реализации адаптера и распределения timeout оставлены исполнителю.

Отказ до отправки запроса создания — `blocked`. Таймаут/разрыв после отправки запроса означает, что вкладка могла создаться: `unknown`, либо `created_unverified`, если уже получены её IDs. Никаких автоматических повторов, ввода в терминал, закрытия вкладки, завершения пользовательских процессов или переключения на `it2 tab new --command`. Отмена ожидания не считается доказательством отсутствия созданной вкладки.

## Проверка запуска и результата

Сохраняется JSON с `mode: launch_codex`, `status`, `window_id`, `tab_id`, `session_id`, `profile`, `findings` и существующими exit codes 0/2/3. Добавляются `launch_mode: handoff|resume` и `resume_session_id` (нормализованный UUID только в режиме resume, иначе null). Не смешивать `session_id` терминала с UUID диалога Codex.

`launched` требует совпадения окна/вкладки/единственной сессии, имени/GUID профиля, `session.profileName`, `session.jobName == codex` и полной ожидаемой команды. `processTitle` используется как имя/путь процесса; `commandLine` должен соответствовать этому процессу, допустимым нулю–двум `--no-daemon` от штатных wrappers и точному argv выбранного режима. Разрешены только документированные положения wrapper-флагов, подтверждённые тестами. `codex --help`, `--version`, голый `codex`, другой cwd/UUID/handoff и частичные наблюдения не дают `launched`.

- **Handoff:** `launched` подтверждает запуск, получение поручения отдельно доказывается свежим безопасно прочитанным `ack.json` с request UUID, фактическим новым thread ID, canonical cwd, accepted_task и first_step. Сохраняется reference с 120-секундным сроком, bounded reads и запретом повторной отправки prompt.
- **Resume:** ack от модели не нужен, поскольку нового задания нет. CLI подтверждает запуск команды resume нужного UUID. До заявления «диалог восстановлен» скилл дополнительно проверяет восстановленную историю/идентификатор в целевой вкладке read-only. Если это наблюдение недоступно — сообщает «команда resume запущена, восстановление истории не подтверждено». Не вводит prompt, `/status` или команды выхода ради проверки. Источник найденного UUID и целевая вкладка должны быть однозначны.

## Объём изменений

- `iterm2_utils/cli.py`, `launch_checks.py`, `launch.py`: режимы, валидация, API-создание, результат и проверки argv; небольшой изолированный SDK-адаптер при необходимости.
- Точный lookup resume переиспользует существующие helpers журнала. Legacy restore/picker, его протокол открытия вкладок и штатный запуск без `launch-codex` не переделываются; не меняем общее поведение `ITerm.new_tab` для остальных потребителей.
- `skills/iterm2-launch/SKILL.md` и references: оба сценария, prerequisite SDK, настоящий custom command, корректная проверка argv, разные критерии получения handoff и восстановления истории; запрет отправки shell-команды в уже работающий Codex.
- README, compatibility matrix, export allowlist/архив, fixtures CLI/launch/preflight/export и структурный validator скилла согласуются с новым поведением.
- Установленный скилл обновляется штатным bootstrap с receipts/CAS после проверки исходника; чужие файлы не перезаписываются. Публичный пакет не содержит личных путей, session UUID пользователя и материалов текущего чата.
- Существующая спецификация launch остаётся исторической; новая явно заменяет её предположение о `it2 --command` и ограничение «нет resume».

## Проверка и приёмка

Разработка и автоматические тесты следуют AGENTS.md: TemporaryDirectory, fake Runner/SDK, никаких чтений или изменений реальных настроек, запуска GUI и изменения разрешений. Baseline фиксируется отдельно от результатов изменений.

Обязательные регрессии:

1. Два режима, прежний handoff argv, ошибки взаимоисключения/UUID/cwd/handoff/неизвестной сессии, другой effective CODEX_HOME.
2. Профиль с собственной командой `codex`: fake SDK должен зафиксировать custom command **при создании**, без вызова `it2 tab new` и без последующего ввода. Один вызов создания; точные окно/профиль; конкурентное изменение активной вкладки не влияет.
3. Нет SDK/API/доступа — нет мутации. Неопределённый результат создания — нет второго вызова и ложного успеха; известные IDs сохраняются. Несовпадение инвентаря/профиля/argv оставляет непроверенный статус.
4. Реальная исполняемая fixture shell с фальшивым Codex проверяет argv обоих режимов, wrappers, `CODEX_RESTORE_NO_AUTO`, пробелы/кириллицу/кавычки/переводы строк/метасимволы в путях. Тексты handoff не выполняются как код.
5. `processTitle=codex`, `commandLine=codex <точные аргументы>` проходит; helpers/пустой Codex/чужой UUID не проходят. Добавить примеры в проверки скилла, чтобы ошибочное требование равенства не вернулось.
6. Bootstrap обоих скиллов и запуск из распакованного релиза; существующий restore остаётся автономным. Запустить требуемые AGENTS.md unit/skill checks и относящиеся export/shell проверки.
7. Поведенческая проверка инструкции свежим Codex на изолированных вымышленных задачах, не содержащих формулировки ответа: новый агент, resume, неизвестный исход создания, команда оказалась в prompt. Не открывать реальные вкладки в этой проверке; fake tools/данные должны обнаруживать неверные действия. Зафиксировать фактический результат и ограничения, а не считать структурный validator доказательством поведения.

**Живая приёмка отделена от разработки.** Предлагается согласовать её этим документом: после fixture-проверок предупредить пользователя и создать две собственные тестовые вкладки с выбранным совместимым профилем через новую CLI. Первая — новый Codex в приватном временном cwd с безвредным handoff, записью ack и ожиданием; после штатного выхода этого тестового Codex вторая — resume UUID именно тестового диалога, без нового prompt. Проверить реальные cwd/argv/IDs, получение handoff, восстановленную историю и отсутствие вставленной shell-команды. При успешном завершении закрыть только эти собственные тестовые вкладки; при неопределённом исходе сохранить их и артефакты, не повторять запуск. Использовать обычные настройки модели/API, не менять профили или разрешения; неожиданный диалог доступа завершает проверку с явным статусом. Не использовать пользовательскую рабочую историю как тестовую fixture.

## Границы и риски

Не исправляем сам bundled `it2`, не добавляем второй транспорт/fallback, автоматическую установку SDK, менеджер сессий, автоотправку сообщений при resume, произвольные аргументы Codex или функции Claude Code.

Официальный SDK становится prerequisite только для `launch-codex`. Отказ API должен быть понятным и происходить до создания вкладки, когда это возможно. Даже успешная команда не гарантирует получение задания или восстановление истории — эти результаты по-прежнему подтверждаются отдельно. Живой опыт сегодняшнего resume не заменяет новую приёмку двух режимов. Установка скилла и fixture-тесты не доказывают живое копирование EN/RU.

Открытых продуктовых вопросов после выбора режимов нет. Точные имена внутренних helpers, расположение минимального SDK-адаптера и организация тестовых doubles оставлены исполнителю в пределах описанных контрактов.
