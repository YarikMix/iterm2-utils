# Запуск самостоятельного Codex в новой вкладке iTerm2

Статус: согласовано пользователем переходом к `superpowers:writing-plans`. База: `24789a8e861cc676982cc4990ba7bce7a3b6cf46`.

## Задача и решения пользователя

Агент должен по поручению пользователя открыть самостоятельную сессию Codex в новой вкладке iTerm2, передать ей задачу и сообщить проверенный результат. Первая версия — только Codex. Пользователь выбрал отдельный навык и небольшую команду запуска в публичном `iterm2-utils`; личная глобальная память направляет агента к навыку.

Повод: агент создал вкладку с Default и запустил Codex 0.166.0 с `--no-alt-screen`. Наш профиль отправляет Cmd+C в Codex для копирования внутреннего выделения, а этот флаг переводит историю в режим терминала. Профиль может быть применён, но копирование выделения iTerm2 через него не работает. Обычный перезапуск устранил наблюдавшийся сбой. Контрольное воспроизведение двух запусков ещё не проведено; причинная связь подтверждена командой запуска и исходниками, а не новым живым экспериментом.

## Подходы

1. Только навык с командами `it2`: меньше кода, но агент заново собирает команду и может изменить параметры или пропустить проверки.
2. Навык и узкая CLI-команда: параметры, адресация вкладки и обработка ошибок закреплены в тестируемом коде; навык готовит контекст и проверяет получение задачи. **Выбран пользователем.**

## Предлагаемый интерфейс

`python3 -m iterm2_utils launch-codex --window WINDOW_ID --profile PROFILE_NAME --cwd ABS_DIR --handoff ABS_FILE --json`

Это предложение автора спецификации. Все четыре значения обязательны: нет выбора текущего активного окна по умолчанию. Навык получает окно родительской сессии по её явному ID, проверяет наличие профиля и передаёт точные значения. Если исходную сессию нельзя определить, уточняет окно у пользователя. Профиль можно использовать установленный пакетом или существующий совместимый пользовательский; имя не зашито в код.

Команда создаёт только одну новую сессию. Нет произвольных аргументов Codex, shell-команды из пользовательского текста, resume, выбора модели, собственного менеджера агентов или настройки интеграций. Существующие настройки Codex, shell-функция запуска, модель и endpoint сохраняются. Никаких установок, новых разрешений и переключения чужих вкладок.

## Поведение команды

1. До создания вкладки проверить macOS, доступность совместимого `it2`, исполняемого Codex, явного окна, профиля, существующего каталога и читаемого обычного handoff-файла. Диагностика выводит только относящиеся к запуску поля, без содержимого handoff, секретов и полных настроек.
2. Проверить фактические привязки Cmd+C/Ctrl+C EN/RU выбранного профиля и отсутствие несовместимой конфигурации Codex для стандартного запуска: `tui.alternate_screen = never` или отключённый собственный полноэкранный transcript. Не исправлять настройки автоматически; вернуть конкретную причину и направить к `iterm2-setup`. Поддерживаемую схему конфигурации и способ чтения ограниченного набора полей подтвердить при реализации. Неизвестную совместимость не выдавать за проверенную.
3. Создать вкладку через `it2 tab new` с явными `--window`, `--profile` и `--command`. Команда создания переопределяет стартовую команду профиля, чтобы профиль с собственным запуском Codex не создавал второго процесса. Профиль применяется с момента создания, ожидание APS не нужно.
4. Запустить через обычный интерактивный login zsh пользователя команду `codex -C ...` с коротким стартовым поручением прочитать handoff. Сохранить штатную shell-функцию `codex` и её интеграции. Не добавлять `--no-alt-screen`, собственные model/API/config overrides или отключение защит. Пути и текст передавать с корректным shell quoting; содержимое handoff не исполнять как shell-код. Перед запуском shell установить только для создаваемого процесса существующий `CODEX_RESTORE_NO_AUTO=1`: он подавляет startup-восстановление в `codex-resume.zsh`, не отключая интеграцию запущенного вручную Codex. Не запускать параллельно восстановленную сессию.
5. Разрешить идентификатор созданной вкладки в единственную сессию именно выбранного окна; проверить применённый профиль. Результат JSON содержит `window_id`, `tab_id`, `session_id`, профиль и статус. `launched` означает подтверждённый запуск Codex в созданной сессии, но не получение поручения и не живую проверку clipboard. Если доступное наблюдение подтверждает лишь создание вкладки, вернуть `created_unverified`, не `launched`.
6. Все внешние вызовы имеют ограниченное время ожидания. При неопределённом исходе создания вкладки или запуска не повторять действие автоматически. Вернуть известные ID и статус `unknown`; навык сначала осматривает уже созданную вкладку. Не закрывать её и не завершать процессы пользователя при ошибке.

## Поведение навыка `iterm2-launch`

- Активируется при просьбе открыть отдельного Codex/поручить работу новому агенту в новой вкладке. Не применяется к внутренним субагентам и Claude Code.
- Передаёт рабочую область, исходное поручение, ограничения, полезные материалы и ожидаемый первый шаг в отдельном локальном handoff. Не превращает передачу контекста в согласованную спецификацию. Объём передаваемых данных ограничен задачей.
- Для каждого запуска готовит уникальный handoff и путь подтверждения рядом с ним. Просит нового агента после чтения записать подтверждение: идентификатор диалога, принятая задача, рабочая папка и первый шаг. Новый файл не должен быть принят за подтверждение предыдущего запуска; оба пути уникальны. Файлы сохраняются для диагностики, автоматического удаления нет.
- Предупреждает о появлении вкладки, вызывает CLI, затем по возвращённому ID проверяет запуск и подтверждение получения. При отсутствии подтверждения за ограниченный срок сообщает «вкладка создана, получение поручения не подтверждено» и даёт ID. Не отправляет поручение второй раз автоматически.
- Для подтверждения достаточно адресного чтения через `it2`; MCP iterm2-observe может использоваться при наличии, но не обязателен. Разрешения не обходятся через другой инструмент.
- Наличие профиля и запущенного процесса не объявляется доказательством живого копирования. Конкретный результат проверки всегда отделён от предположений.

## Встраивание и объём изменений

- CLI: новая подкоманда и небольшой модуль запуска; обработка ошибок соответствует существующим JSON/status conventions.
- Транспорт `it2`: переиспользовать или минимально выделить существующие операции из `runtime/codex_restore/codexlib/iterm.py`. Сохранить timeout, проверку ID и `UnknownTabOutcome`. Не дублировать полный клиент и не делать запуск зависимым от включённой функции restore. Существующий установленный restore обязан остаться автономным; размещение общего кода и его экспорт — решение реализации с тестом обоих потребителей.
- Новый `skills/iterm2-launch/SKILL.md` и необходимые references. Установщик навыков получает явный выбор `bootstrap-skill --skill iterm2-launch --agent codex`; без `--skill` сохраняется прежнее поведение установки только `iterm2-setup`. На первой версии новый навык устанавливается только для Codex. Receipts/CAS и сохранность чужих файлов обязательны.
- README, структурная проверка навыков, список файлов релиза, тесты CLI/bootstrap/restore и документация совместимости обновляются вместе с функцией. Навык использует доступный checkout/распакованный релиз; не предполагает приватного пути автора.
- После готовности навыка обновить существующую личную заметку о новых вкладках и её описание в индексе памяти: направить к навыку, указать несовместимость `--no-alt-screen` с профилем. Личные пути и paiw-правила не входят в публичный пакет. До готовности не создавать ссылку на несуществующий установленный навык.

## Проверка и границы

Автотесты на TemporaryDirectory HOME и fake adapters: неверные входы не создают вкладку; точный выбор окна/профиля; отсутствие `--no-alt-screen`; shell quoting для пробелов, кириллицы, кавычек, `$()` и переводов строк; отсутствие двойного старта из profile command/restore startup; таймаут после создания не порождает повтор; корректное разделение created/launched/received; ошибки профиля и несовместимых настроек; сохранность чужих bootstrap-файлов; экспорт и независимость restore от исходного checkout. Запустить обязательные проверки репозитория и регрессию затронутого restore.

Для навыка — отдельная поведенческая проверка: открытие новой сессии с handoff, неопределённый результат запуска, отсутствие профиля. Структурный validator не заменяет такой прогон; недоступность авторизации явно отражается в отчёте.

Живая приёмка: в изолированном Mac-контуре с тестовым HOME/настройками создать вкладку из другого агента, подтвердить профиль и получение handoff, проверить Cmd+C → Cmd+V EN/RU без автокопирования и без ручного перезапуска, проверить сохранность соседней сессии. Правила репозитория запрещают использовать реальные настройки/рабочие сессии разработчика для разработки и приёмки. Если изолированного контура нет, live-пункт остаётся непроверенным; fixtures не объявляются заменой. Для проверки в личном окружении потребуется отдельное явное разрешение пользователя на исключение из этого правила.

Не входят: поддержка Claude, исправление исходной гонки больших clipboard, автоматическая смена глобальных настроек, массовый запуск, восстановление старых диалогов, публикация релиза и универсальный оркестратор.
