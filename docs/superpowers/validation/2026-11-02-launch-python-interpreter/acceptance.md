# Проверка инструкции выбора Python и окна

Дата: 2026-11-02. Изменены только скилл и примеры README; код CLI не менялся.
Спецификация: [выбор Python и окна](../../specs/2026-11-02-launch-python-interpreter-design.md).

## Поведенческие пробы

До изменения инструкции зафиксированы 27 вымышленных случаев: 5 для Python и
11 для выбора окна, каждый из последних в режимах handoff и resume. Случаи не
менялись после получения ответов и не скопированы в примеры скилла.
Для каждого варианта выполнено по 5 независимых свежих процессов: краткая
контрольная инструкция без новых правил, полный старый скилл, полный новый скилл.
Итого 15 процессов, 405 решений. Ответы просмотрены вручную, включая объяснения.

Использован `codex exec --ephemeral --sandbox read-only` с явно переданным снимком
текста, отключёнными shell/MCP/apps/multi-agent и без проектных инструкций.
Каждый ответ вернул SHA-256 именно переданного снимка. Во всех 15 потоках событий
нет вызовов инструментов. Это текстовые решения, а не исполнение процедуры.
Запуск настроенной модели `gpt-6-astra` через корпоративный API разрешён пользователем.
`claude -p`, указанный в плане, недоступен: команда отсутствует. Замена на свежие
Codex-процессы сохраняет независимость от кэша текущей сессии, но не проверяет
discovery или поведение Claude. В логах есть предупреждения о пропущенных старых
определениях ролей; все процессы завершились с кодом 0 и валидными ответами.

| Проверяемое решение | Контроль | Старый скилл | Новый скилл |
| --- | --- | --- | --- |
| Отсутствующий/устаревший родитель, одно окно: без лишнего вопроса | 20/20 | 0/20 | 20/20 |
| Исчезнувшее выбранное окно: без автоматической замены | 0/10 | 10/10 | 10/10 |
| Противоречащие привязки родителя: запрос явной цели | 0/10 | 10/10 | 10/10 |
| Сохранение выбранного абсолютного Python (P1/P3/P4/P5) | 20/20 | 20/20 | 20/20 |
| Нет SDK: остановка без установки/поиска другого Python | 5/5 | 5/5 | 5/5 |

Новая инструкция: все 135 решений соответствуют выбранной цели/остановке,
пути Python и указанным в заданиях проверкам. Отдельно проверены приоритет явного
окна, живого родителя, несколько/ноль окон, ошибка API, исчезнувшая явная цель и
появление второго окна перед запуском. Вариации поля `window` для отказа (null
либо прежняя цель) допустимы: оценивается отсутствие запуска/подмены.
Для W11 запрос новой цели в старой инструкции считается безопасной остановкой.

Контроль при противоречии родителя предлагает перечитать API вместо явного выбора;
это не опасный запуск, но не соответствует согласованному решению W8. Контроль
содержит только краткий контракт CLI, поэтому его неверные конкретные help-команды
не используются как доказательство улучшения выбора Python. На метрике сохранения
Python улучшение не обнаружено; правка делает уже требуемое правило исполнимым
примером и явно требует повторной проверки после смены контекста.

Независимое ревью и штатный bootstrap/CAS: ожидаются; результаты будут добавлены

## Ограничения

Новые handoff/resume-вкладки не создавались. Не проверены свежая доставка ack,
восстановление истории, clipboard и новая сессия с автоматическим discovery скилла.
Полный API-инвентарь и повторная проверка выбранного окна не дают атомарности
при одновременном изменении окон другим процессом. Исходные пробы, снимки и логи
сохранены приватно в worktree; они не входят в публичный экспорт.
