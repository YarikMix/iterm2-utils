# Выбор Python и окна для iterm2-launch — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Агент использует один проверенный Python и выбирает единственное окно по API без лишнего вопроса при отсутствующем родителе.

**Architecture:** Уточняем текст скилла и относящиеся примеры README. CLI уже использует `sys.executable`; его интерфейс и код остаются прежними. Установленный скилл обновляем через существующий bootstrap/CAS.

**Tech Stack:** Markdown, zsh, Python 3.11+, существующие unittest и validators.

**Spec:** [Согласованная спецификация](../specs/2026-11-02-launch-python-interpreter-design.md).

## Global Constraints

- Python **3.11+**; живая проверенная версия SDK **2.23**, без заявления о новой live-приёмке.
- Один абсолютный `sys.executable`; не разыменовывать symlink virtualenv, не подменять путь shim-ом.
- `launch_python` заключён в кавычки; значение явно переносится между отдельными tool-вызовами.
- Каждая внешняя preflight-проверка ≤10 секунд; ошибка останавливает процедуру до создания вкладки.
- При смене cwd/PATH повторно проверять сохранённый Python в контексте вызова.
- Не менять CLI/JSON, зависимости, настройки, исторические спецификации; не привязывать продукт к mise или личным путям.
- Не устанавливать SDK и не искать окружения автоматически; явная установка пользователем остаётся отдельным действием с повторной проверкой.
- Поведенческие пробы используют вымышленные данные; никаких настоящих вкладок или изменения настроек в тестах.
- Приоритет окна: явный выбор → подтверждённый родитель → единственное окно полного валидного API-инвентаря при отсутствующем/устаревшем runtime ID → уточнение неоднозначности. Ошибка API не означает отсутствие родителя.
- Перед запуском повторно проверить цель; для выбора по единственности должно оставаться ровно то же окно. Не подменять исчезнувшую явную цель и не выбирать по фокусу.

## Review Focus

1. Python с SDK отличается от `python3` после смены PATH — сохраняется первоначальный абсолютный путь.
2. SDK отсутствует или Python старше допустимого — нет запуска и автоматического ремонта окружения.
3. Путь содержит пробелы; shell-переменная потерялась между вызовами — явная передача корректного argv.
4. Python внутри virtualenv является symlink — не переходить к базовому интерпретатору.
5. Устаревший родитель и изменение окон — единственное окно без вопроса, неоднозначность с уточнением, исчезнувшая явная цель без подмены.

Дополнительно сохраняется проверка смены cwd: импорт SDK/пакета перепроверяется в новом контексте.
