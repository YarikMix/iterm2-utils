# iterm2-utils Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить публичный набор из семи выбираемых улучшений iTerm2 и общий скилл настройки для Codex/Claude Code.
**Architecture:** Три последовательных плана дают самостоятельно проверяемые приращения одного продукта: CLI и профили, runtime-интеграции, полный цикл установки и скилл. Все модули используют один журнал владения настройками; одновременно редактировать его реализацию разными исполнителями нельзя.
**Tech Stack:** macOS, zsh, Python 3.11+ standard library, unittest, iTerm2 Dynamic Profiles/it2/штатный Claude installer; optional terminal-notifier, fzf, uvx, Peekaboo.
**Spec:** [2026-10-22-iterm2-utils-design.md](../specs/2026-10-22-iterm2-utils-design.md).

## Global Constraints

- «Агент сначала уточняет у коллеги, какие фичи подключить»; невыбранные возможности не включаются.
- «Codex-профиль никогда не назначается `claude`»; правило копирования — `&codex`.
- `tui.copy_on_select = "never"`; `CopySelection = false` только при выборе clipboard.
- MCP: `mcp-server-iterm2==0.1.1` с `mcp<2`, отдельная выбираемая фича.
- «Hooks адресуют явный UUID вкладки»; нельзя подставлять активную вкладку.
- «Peekaboo не устанавливается скрытно»; системные разрешения и hook trust подтверждает человек.
- «Старые репозитории и текущая рабочая установка автора при разработке нового пакета не изменяются».
- «Версии внешних зависимостей и происхождение перенесённого кода записаны явно».
- «Установка идемпотентна»; удаление восстанавливает только собственные неизменённые значения.
- Поддержка первого выпуска: macOS + zsh; Python 3.11 выбран для корректного TOML через tomllib, а не как требование спецификации.

## Review Focus

1. Существующая функция/alias `codex`, старые hooks и одноимённый MCP — отсутствие второй установки и явный конфликт. Тест: III/9.
2. Symlinks, Unicode, `ZDOTDIR`/`CODEX_HOME`, одновременная правка файла — сохранение адресата и чужих данных. Тест: I/2.
3. Удаление одной фичи при наличии общей зависимости — сохранение runtime/профиля для оставшихся. Тест: III/9.
4. Неизвестный UUID, timeout после отправки события, API без доступа — отсутствие повторного открытия/чужого уведомления. Тест: II/5–8.
5. Только Claude, только Codex, уведомления без статусов, hotkeys без clipboard — отсутствие скрытой установки других фич. Тест: I/1, II/5–6, III/10.

## Порядок и границы

1. [I. Основа, профили и shell](2026-10-22-iterm2-utils-01-core.md), задачи 1–4. Результат: read-only doctor, явный выбор, установщик clipboard/shell/hotkeys с безопасным удалением.
2. [II. Runtime-интеграции](2026-10-22-iterm2-utils-02-integrations.md), задачи 5–8. Результат: независимо выбираемые статусы, уведомления, восстановление, MCP.
3. [III. Миграция, скилл и выпуск](2026-10-22-iterm2-utils-03-delivery.md), задачи 9–11. Результат: полный update/uninstall, сценарий установки агентом и публичный проверенный выпуск.

Состав фич общий, поэтому три плана исполняются по порядку, а не тремя независимыми продуктами. Ревьюер может отдельно отклонить runtime уведомлений или восстановление, не отменяя готовую основу. Публикуется весь согласованный набор, а не незаметно урезанный первый этап.

## Зафиксированные решения поставки

- Нет pip-install для пакета: `python3 -m iterm2_utils` из checkout. При install runtime копируется в версионированный каталог `~/.local/share/iterm2-utils/releases/<version>/`; стабильная ссылка `current` меняется только после проверки payload. Перемещение checkout после установки не ломает hooks.
- Собственные настройки/receipts: `${XDG_CONFIG_HOME:-~/.config}/iterm2-utils/`; state/backups — 0700/0600. Состояние runtime отдельно в `${XDG_CACHE_HOME:-~/.cache}/iterm2-utils/`. В logs нет prompts/transcripts/payloads.
- Новая установка использует собственные command hooks `iterm2-utils`, повторно используя runtime статусов; второй Codex plugin marketplace не нужен. У существующего `iterm2-status` статусы reuse без дублирования; передача владения только через явный `--adopt-legacy` в задаче 9.
- Лицензия нового кода MIT, upstream notices сохраняются. Публичная база статусов: `YarikMix/iterm2-status` commit `e749ff64a6b34252e9f41c5103f4b46831691443` (доступность проверена). Более новый локальный snapshot не является доступной публичной зависимостью; нужные отличия переносятся как обозримые локальные изменения с тестами, а не как ссылка на недоступный SHA.
- Официальный zsh script: iTerm2 tag `v3.7.6`, `Resources/shell_integration/iterm2_shell_integration.zsh`, SHA-256 `785f18e203c29c8d06a9cd374d0831748909f5c6143175287817764681f840a7`; сохранить его GPL notice отдельно от MIT нового кода.
- До исполнения: применить using-git-worktrees, создать отдельный локальный Git repo/worktree, поскольку сейчас есть только SDD-документы. Не создавать remote до задачи 11. Собственные коммиты по завершении задач, без чужих файлов и без force-push.
